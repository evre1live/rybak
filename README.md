# Рыбак

Рыбалка с друзьями от первого лица: зашли в бухту, включили голос — болтаем и ловим.
Улов продаётся на рынке, на выручку покупаются удочки, леска, катушки, наживка и приманки.
Каждый играет за одного из девяти героев — у каждого своё телосложение, возраст, характер и свои цвета.
У пирса дают напрокат лодку с мотором: на ней выходят в открытое море, к затонувшему кораблю,
на Пальмовый остров и к причалу у маяка — и ловят прямо с борта.
Море за бухтой живое: зыбь и барашки по ветру, скалы с отмелями (Зубья, Чаячий камень, Западные камни), вехи с огнями
на пути, стаи чаек над морскими косяками, дельфины и лесистые острова на горизонте.

## Запуск

```bash
npm install
npm start          # http://localhost:3000
```

Клиент уже собран (`public/app.js`). После правок в `client/` или `shared/` пересоберите: `npm run build`
(или `npm run dev` — пересборка при каждом сохранении).

Выкладка на Render: New → Blueprint → этот репозиторий. Настройки лежат в `render.yaml`.

Пробная версия одним файлом, без сервера (только одиночная рыбалка): `npm run solo` → `dist/rybak-solo.html`.

## Как устроено

- `shared/data.js` — рыба, снасти, зоны бухты, часы; `shared/logic.js` — клёв, выбор рыбы, вываживание, цены, рынок, профиль,
  а ещё погода (`weatherAt` — по зерну комнаты и часам, у всех одна), задания дня (`makeQuests`, `questEvent`) и турнир
  (`tourAdd`, `tourTable`, призы и медали).
  **Вываживание** (`fightInit`, `fightStep`): у каждой рыбы своя манера (`FISH[].style`, названия и подсказки —
  `FIGHT_STYLES`): бегун (длинные частые рывки), прыгун (свечи: пока рыба в воздухе, «опасно» на шкале начинается
  с 62 %, а подмотка тянет в полную силу — кнопку надо отпустить), тяжеловес (редкие рывки, идёт только на леске
  внатяг), трясун (стрелка дрожит), хитрец (не увёл от укрытия — леска заходит за камни), присоска (залегает:
  отрывают, держа стрелку в рамке 60–78 %). Легенды (редкость 4) дважды собираются с силами — на 45 % и 80 % пути
  забирают часть лески и делают длинный рывок. Множители манер и «второго дыхания» — в `STYLE_K` и `FIGHT_K`;
  они подобраны так, чтобы доля вытащенных по видам, снастям и умению осталась прежней (бот `botFight`, сверка —
  тест «баланс манер»). Время боя (`s.t`) и усталость рыбы (`s.fat`) — разные часы.
- `server/` — Node + ws: комнаты по коду из 4 символов, рассылка положений 12 раз в секунду, события, чат, голос.
  Рыбалка считается в браузере игрока; сервер держит общие часы бухты и зерно комнаты (по нему у всех одинаковые
  цены на рынке, косяки рыбы и погода) и ведёт турнир: его объявляет хозяин комнаты (`{ t: 'tour', a: 'start', kind, len }`),
  очки считаются на сервере по событиям улова, итоги приходят всем (`tscore`, `tend`).
  **Сохранения и таблица рекордов** (`server/api.js`, `server/store.js`, общее — `shared/cloud.js`): если серверу дана
  база Postgres (`DATABASE_URL`; на Render её подставляет сам Render — см. `render.yaml`), он хранит сохранения игроков
  и ведёт таблицу рекордов. Учётных записей нет: сохранение открывает «код сохранения» — 16 знаков, которые игра
  придумывает на устройстве; в базе лежит только отпечаток кода. Запросы: `POST /api/save` (запись сверяет номер версии
  — опередило другое устройство, вернётся отказ `CONFLICT` с описанием того, что на сервере; опыту уменьшиться без
  `force` не дают), `POST /api/load`, `POST /api/forget`, `GET /api/top`, `GET /api/status`. Таблицы заводятся сами при
  запуске; в `history` лежит запас — каким сохранение было в начале каждого игрового дня (30 дней). При запуске сервер
  делает самопроверку базы (запись, отказ, чтение, стирание служебной строки) и пишет итог в журнал. Без базы игра
  работает как раньше, сохранения — только в браузере. Для разработки и проверок: `RYBAK_DB=memory npm start` — Postgres
  в памяти процесса (PGlite); `RYBAK_DB=dir:<папка>` — он же с файлами на диске, переживает перезапуск.
  **Комнаты переживают перезапуск сервера.** Комнаты живут в памяти, но каждая записана в базу (таблица `rooms`):
  код, зерно, часы бухты, хозяин, турнир с зачётом и места игроков — номер, цвет, карточка и отпечаток жетона места
  (сам жетон знает только игрок). Запись уходит не позже чем через две секунды после перемены; раз в минуту комнаты,
  где есть люди, отмечаются как живые. Сервер остановили (выкладка: `SIGTERM`) — он записывает комнаты и закрывает
  соединения с пометкой «перезапуск» (код 1012); упал — в базе всё равно то, что было пару секунд назад. Игра сама
  возвращается: первый вернувшийся игрок поднимает комнату из базы (`recall` → `revive`), остальные занимают в ней свои
  места по жетонам. Полминуты после этого прежнего хозяина ждут и не подводят итоги турнира, если он успел кончиться.
  Пустая комната ждёт четверть часа — и в памяти, и в базе. В базу сервер ходит только по делу: код похож на настоящий,
  не чаще положенного с одного соединения, а ненайденный код двадцать секунд не ищется снова. Сервер только что
  запустился и ещё не подключился к базе — вход в прежнюю комнату подождёт её до 15 секунд. Без базы комнаты, как
  раньше, пропадают с перезапуском.
- `client/` — three.js без движка. Мир, вода, удочки и рыба строятся кодом — это запасной вид: он виден,
  пока грузятся готовые модели (и в пробной версии одним файлом), а потом модели встают на те же места.
  - `terrain.js`, `world.js`, `scenery.js`, `water.js` — бухта, свет по времени суток (в `water.js` — и прибой: кромка
    воды «дышит», к берегу идут пенные валы — на крутом берегу и у скал их нет, гребень вала размыт к хвосту, —
    песок у воды мокрый); `places.js` — острова и причалы за бухтой;
  - **открытое море.** `water.js`: за кругом бухты (`SEA`) к ряби добавляется зыбь — две длинные волны, одни и те же
    в шейдере воды и в `waveH` (по ней качаются лодка, буи и поплавок); сила зыби — от ветра (`sea.k`), в бухту она не
    заходит (`seaK`). На гребнях — барашки, отражение в зыби дробится, вода над глубиной темнее. `terrain.js`:
    `SKERRIES` — три группы скал с отмелями (рифовая зона ловли, в камни лодка упирается), `MARKS` — вехи с мигающим
    ночью огнём, `SEA_HOMES` — места морских косяков: над каждым кружит и ныряет стая чаек (издали птицы рисуются
    крупнее настоящих — по ним косяк и ищут), под стаей плещется мелочь, ближе — слышны крики.
    `farisles.js` — дальние острова: настоящий рельеф с пляжами, скалами и лесом вместо зелёных холмов (до них не
    доплыть: ближний берег в полутора сотнях метров за краем карты). `dolphins.js` — две стаи дельфинов ходят по морю
    замкнутой дорогой (`DOLPHIN_WAY`), место стаи считается из общих часов комнаты — все видят их в одной точке;
    дельфины показывают спину, время от времени прыгают целиком, под самой лодкой не выныривают;
  - `surface.js` — фактура всего, что собрано кодом: земля (трава, камень, песок, тропа — рисованные текстуры из
    `public/tex/`, границы между ними ведёт шум), скалы и валуны (та же каменная кладка с трёх сторон, мох сверху),
    дерево, крашеные доски, черепица; `grass.js` — пучки травы и цветы вокруг игрока;
  - `seabed.js` — дно, которое видно с причала и из лодки (до четырёх метров глубины): водоросли пятнами (копии одной
    заготовки, качаются шейдером травы; на «среднем» их 60 %, на «низком» 30 % — `detail.kelp`), камни, ракушки,
    морские звёзды, кораллы у рифа, затонувшие бочки, ящик, якорь и покрышка у пирса и у остова. Статика — один меш
    с цветом в вершинах, новых шейдеров нет. В отражение на воде дно не попадает;
  - `flags.js` — флаги на шестах у причалов (`Flags`: полотнище вытягивается по ветру и обвисает в штиль — так виден
    ветер; одна программа на все флаги) и лучи низкого солнца (`SunRays`: веер света на рассвете и на закате, когда
    солнце в кадре; один треугольник на весь кадр, прибавляется к картинке, ближние предметы его перекрывают;
    в пасмурную погоду, в тумане и на «низком» качестве лучей нет — `detail.rays`);
  - `fishing.js` — рыбалка игрока от заброса до улова. В вываживании рыба ведёт себя по манере (глубина, уход вбок,
    свеча, пенный след в рывке, брызги там, где леска режет воду, капли с лески на пределе). Улов показывается
    двумя способами: без подсака рыба висит на леске под согнутым кончиком удилища (в двух метрах от глаз, поэтому
    в `HANG_K` раз крупнее), с подсаком — лежит на боку в сетке, рукоять которой держит левая рука
    (`viewmodel.js`: `present`, `netSlot`, `hangLine`; модель сетки — `buildNet` в `gear3d.js`). Пальцев у героев
    нет, поэтому рыбу в кулак не кладём: кулак держит рукоять подсака или удилище.
    `startFight(вид)` и `showCatch(вид)` — для проверок и снимков.
  - `main.js` — помимо прочего: на подсечке время на миг замирает, при «втором дыхании» и когда рыба выходит из
    воды — течёт медленнее (`stopTime`); при вываживании поле зрения чуть уже, а взгляд сам держится на рыбе,
    пока игрок не ведёт мышью (выключается в настройках: `settings.follow`).
  - `palette.js` — **палитра**: один набор чисел на всё настроение кадра — цвет неба, солнца, рассеянного света, дымки
    и воды по ключевым часам суток, тональная кривая (насыщенность, «живость», контраст, глубина чёрного, оттенок теней
    и светов), прозрачность воды и сетка света на дне, свечение, виньетка, дальность дымки. `world.js`, `water.js`,
    `surface.js` и `gfx.js` берут числа отсюда. В игре — `tropic` («Тропики»: её пользователь выбрал из трёх вариантов
    этапа 20); для сравнения остались `now` (как было раньше), `pastel` и `cinema` — `?pal=now`. На «высоком» палитру
    можно сменить на ходу (`RYBAK.setPalette('pastel')`); на остальных ступенях тональная кривая вшита в шейдеры
    и берётся при загрузке.
  - `gfx.js` — отрисовка и своя тональная кривая (тени не проваливаются в чёрное, цвет не уходит в рыжий).
    Разрешение — доля от положенного ступени качества (`setScale`, не мельче 540 строк). Отражение мира в воде
    («высокое») рисуется через кадр в свой буфер: в полкадра, в четверть или никак (`setRefl(2|1|0)`).
    `shaders(scene, camera, tier)` собирает шейдеры сцены под ступень качества, не подвешивая страницу
    (`compileAsync`; у «высокого» — с выставленным буфером сцены, иначе соберутся не те); `prepare` до первого
    кадра делает это и отдаёт текстуры видеокарте; `warm(root)` отдаёт текстуры только что загруженной модели —
    по одной за кадр (за заставкой быстрее). Всё это иначе случается рывками посреди игры.
  - `perf.js` — счётчик кадров (окошко по F3) и автоподбор. `pickQuality` — подбор ступени замерами при каждой
    загрузке, в обе стороны, начиная с запомненного (тяжёлый кадр с отражениями должен укладываться в 15 мс: нет —
    отражения в четверть кадра, потом без них; «высокое» без отражений дороже 18 мс — «среднее»; запас большой —
    пробуем ступень выше); `scaleFor` — разрешение по цене кадра. `tuneStep` — на ходу, раз в полсекунды: кадры
    дольше 22 мс или идут неровно (`longShare` — доля кадров, пропустивших обновление экрана; три из тридцати —
    уже рывки) → сначала дешевеют отражения, потом разрешение, потом ступень качества; идёт ровно — разрешение
    возвращается (не во время заброса и вываживания), после неудачной попытки — с удвоенной выдержкой.
    Логика чистая, её проверяет `npm test`. **Разрешение меняется только в начале кадра, до отрисовки**
    (`scaleNext` в `frame`): смена размера стирает холст, и кадр, нарисованный до неё, ушёл бы на экран пустым —
    чёрной вспышкой (так и было, пока автоподбор менял разрешение в конце кадра). На случай, если холст всё же
    сотрут после отрисовки, кадр рисуется заново (`gfx.wiped`). Это проверяет `npm run test:frames`.
  - Загрузка (`boot` в `main.js`): заставка с полосой → модели локации → шейдеры и текстуры → подбор качества →
    кадры за заставкой (обычный, «первый показ», обычный, снимок бухты для карточки места, обычный) → ждём видеокарту.
    На «авто» игра меряет цену тяжёлых кадров с ожиданием видеокарты (`frameCost`: кадр + `readPixels`, берётся
    верхняя четверть) и выбирает ступень, уровень отражений и разрешение; итог запоминается для этой видеокарты
    (`settings.autoQ`) — с него начнёт следующий запуск. Окно в фоне или без размера — замер откладывается.
    Прежде чем упростить картинку на ходу, игра проверяет настоящую цену двух кадров: если они лёгкие, а частота
    низкая — её держит сам браузер (режим экономии), и картинку не трогаем.
    `?boot=full` — пройти загрузку целиком и в проверках (с `?norender` она по умолчанию короткая).
    «Проверка компьютера» в настройках (`bench`) — четыре вида бухты, цена кадра, ход по часам экрана, доля
    неровных кадров и чем кончился подбор при загрузке; отчёт текстом можно скопировать.
  - «Первый показ» (`warmDraw`): собранный шейдер видеокарта доводит до дела только при первой отрисовке с ним,
    поэтому за заставкой один кадр рисуется без отсечения по полю зрения и с показом всего спрятанного (герой,
    руки с удочкой, поплавок, брызги, лодка, дальние копии леса, заготовки рыбы). Иначе каждый предмет, впервые
    попавший в кадр, давал бы рывок. Смена ступени качества (`switchTier` — из настроек, `applyTune` — автоподбором)
    идёт так же: шейдеры новой ступени сначала собираются в фоне, потом картинка переключается и показ повторяется
    (`rewarm`). Если просто переключить, шейдеры собираются разом в ближайшем кадре — на Apple M4 это три секунды.
  - Свет: набор источников у сцены один на всю игру. Фонари (`lampLights`) и подсветка героя (`fill`) днём горят
    «нулём», но из набора не убираются: число источников зашито в шейдеры всей сцены, и смена набора — это новые
    шейдеры и первый показ с ними (на Apple M4 кадр с новым набором шёл 0,7–0,85 с). Пять погашенных фонарей стоят
    там же 0,8 мс на кадр из 13 — дешевле рывка. Программ на всю игру около 60.
  - Прогрев рыбалки: в сцене с самой загрузки невидимо лежат заготовки (`warmBox`: процедурная рыба, модель рыбы,
    хлам) — их шейдеры собираются вместе со всеми. Пока поплавок на воде, подгружаются модели тех, кто здесь
    клюёт (`preloadCatch`: девять поклёвок из десяти, не больше 12 видов, на телефоне 5); модель считается готовой,
    когда её текстуры уже у видеокарты (`setWarmer` в `models.js`, `gfx.warm` — по одной за кадр). К подсечке всё
    на месте — ни сборки шейдеров, ни отправки текстур в начале вываживания. Проверяет `npm run test:warm`.
  - `smalls.js` — мелочь мира (ящики, бочки, кранцы, чайки на сваях): слой 1 — в отражении воды её нет, издали
    не рисуется (`detail.far`). Камера игрока видит слои 0 и 1, зеркальная — только 0.
  - `offline.js` и `public/sw.js` — кэш игры на устройстве. `sw.js` собирает `tools/build.js` из `tools/sw.src.js`:
    список файлов с отпечатками содержимого и номер версии. Игра открывается из кэша (и без сети, и пока сервер
    спит), остальные файлы докачиваются в фоне, после обновления заново качается только изменённое. На заставке
    новая версия включается сама (страница перезапускается), посреди игры — со следующего запуска.
    На localhost кэш выключен (правки были бы не видны): `?sw` — включить, `?nosw` — снять совсем.
    `manifest.webmanifest` и значки — чтобы игру можно было поставить как приложение.
    На «высоком» качестве: свечение, отражение мира в воде (сцена глазами зеркальной камеры — в буфер половинного
    размера, через кадр) и мягкая тень в углах по буферу глубины. Для проверок: `?refl=0` — без отражений,
    `?ao=0…1[,радиус,сила]` — затенение; на ходу — `RYBAK.gfx.reflect` и `RYBAK.gfx.aoK`;
  - `hero.js`, `models.js` — готовые модели героев, рыбы и предметов; `envmodels.js`, `scatter.js` — модели локации:
    лес и камни сотнями копий (рядом — подробные и с тенью, вдали — грубые), маяк, домик смотрителя (ночью в нём
    горят окна), корабль, хижина, будка проката, фонари, скамейки, указатель, чайки, костёр;
  - `boat.js` — лодка напрокат: ход, качка, след за кормой, лодки друзей; в чужую лодку можно сесть пассажиром
    (`Ride`: два места на передней банке; в состоянии игрока по сети — чья лодка и какое место).
    **Своя лодка** (`ITEMS.boat`, лавка, «Прочее»): выходы без платы, сдавать её не нужно; на носу — вымпел, на банках —
    подушки цвета игрока (цвет его метки на карте; `BoatVisual.setOwner`, друзьям уходит флажком `FLAG.own`).
    Вымпел — тот же материал, что у флагов на берегу: у причала смотрит по ветру, на ходу вытянут к корме;
  - `postcard.js` — открытка (клавиша **P**, на телефоне — кнопка при улове): кадр игры 1600 × 900 с подписью — вид,
    вес, отметки, имя и дата; без улова — вид бухты. Подписи (`cardText`) собираются отдельно от рисования
    (`drawCard`) и проверяются тестом. Скачивается файлом, на телефоне — через «Поделиться»;
  - `weather.js` — струи дождя; небо, свет, туман и круги на воде по погоде — в `world.js` и `water.js`.
    Под навесами лавки и будки проката сухо (`ROOFS`). В дождь мир намокает (`world.wet`, в шейдере — `uWet`):
    доски и камень темнеют и отсвечивают небом, на ровном настиле стоят лужи; трава и листва только темнеют.
    Намокает за четверть минуты, сохнет больше минуты.
  - `fauna.js` — живность, три вызова отрисовки на всё: стайки мальков (движение в шейдере, от шагов по воде, поплавка
    и лодки шарахаются — `scare`), рыба покрупнее (косяки из `scenery.js`, одиночки у свай и рифа, рыба, которая
    подходит к наживке за несколько секунд до поклёвки, — `bait`, и рыба, которая играет на поверхности: расписание
    всплесков общее для комнаты), бабочки и стрекозы днём, светлячки ночью. Рыба рисуется после воды и сама считает,
    сколько воды над ней; издали от неё остаётся тёмная тень. В камни, под настил и на мель живность не ставится
    (`inRocks` в `terrain.js`; у `deckAt` отступ наружу — отрицательный).
    **Рыбалка по живой рыбе:** тени одиночек — настоящая рыба. Положили наживку рядом с тенью (`notice`: ближе 3,4 м,
    но не на голову — ближе 0,9 м рыба пугается) — эта рыба и клюнёт: поклёвка приходит быстрее (`biteDelay` ×2,4),
    размер из верхней части вилки вида, хлама не бывает, в карточке улова «ВЫСЛЕЖЕНА», опыт ×1,2 (`rollFish`,
    `spot.big`). Приманку можно провести мимо тени — рыба бросится за ней. Бег и прыжки по настилу, чужая снасть
    рядом — распугивают (`scare`, `spook`); пойманная одиночка возвращается на своё место через несколько минут.
    `?w=clear|cloudy|rain|fog` — погода насильно, для проверок;
  - `character.js` — персонаж: игрок выбирает героя, других персонажей нет. Кукла из частей, с которой игра начиналась,
    осталась невидимым «скелетом»: по ней считаются позы, герой их повторяет. Пока модель героя грузится, персонажа
    не видно; саму куклу видно только там, где моделей нет вовсе (пробная версия одним файлом);
  - `viewmodel.js`, `fparms.js` — удочка и руки героя от первого лица (у них свой угол обзора, от настроек не зависит);
  - `gear3d.js`, `fish3d.js`, `icons.js` — снасти, рыба, значки и портреты;
  - `player.js`, `fishing.js` — управление и сама рыбалка; `remote.js` — друзья.
    **Подсак друга:** в бою игрок рассылает пройденный путь (поле `K` состояния). Друг с пустыми руками не дальше
    `ASSIST_REACH` (3,4 м) видит подсказку, а с `ASSIST_AT` (70 % пути) — кнопку «Подсачить». Просьба идёт событием
    `assist`; решает игра рыбака (`assistBlock`: не в свече, не со дна, у легенды — только после второго «дыхания»)
    и отвечает уловом с именем помощника либо причиной отказа. Рыбаку — улов, помощнику — четверть опыта (`recordAssist`);
  - `profile.js` — сохранение в браузере. **Перенос сохранения** (Настройки → «Сохранение и перенос»): «Сохранить
    в файл» (`exportSave`) и «Загрузить из файла» (`importSave` — та же починка, что при обычной загрузке; чужой, битый
    и из будущей версии файл не принимается); после подтверждения игра открывается заново с загруженным прогрессом;
  - `cloud.js` — **сохранение на сервере**. Главным остаётся сохранение в браузере; на сервер оно уходит через 12 секунд
    после изменения и при сворачивании страницы. Другое устройство подключается по коду сохранения (та же панель).
    Если на сервере версия новее, а на этом устройстве с прошлой сверки не играли (сверяется «отметка прогресса»
    `markOf`: опыт, монеты, улов, покупки — задания дня и прочее, что игра пишет сама, не в счёт), прогресс
    подменяется на месте, без перезапуска. Играли на обоих — запись на сервер останавливается, и игрок сам выбирает,
    какое сохранение оставить. Сброс прогресса и загрузка из файла уходят на сервер как решение игрока (`force`).
    Таблица рекордов — панель «Рекорды» (заставка, пауза): рыбаки по опыту и рекорд по каждому виду; себя можно
    скрыть, а хранение на сервере — выключить (сохранение при этом стирается с сервера);
  - `net.js`, `voice.js` — связь и голосовой чат (WebRTC, при строгой сети — через сервер);
  - `ui.js` + `public/style.css` — интерфейс. **Экран игры** (этап 19, по макетам из `claude/rybak-plan.md`): стеклянные
    скруглённые панели, один прямой шрифт (Onest), акценты — бирюза и розовый. Слева вверху — место, время и погода,
    задания дня; сверху — компас с градусами (убирается в настройках); справа вверху — где мы и широкая мини-карта
    (512 × 276: бухта или всё море), под ней команда: у каждого игрока своя фигурка и цвет (`MARKS` в `proto.js` — те же
    над головой в мире и на карте), огонёк «говорит» и микрофон, ниже — монеты и уровень; слева внизу — плашка
    «улов | наживка»; справа внизу — подсказки управления по строке на действие (клавиши, кнопки геймпада) и чип удочки;
    снизу по центру — вываживание: «Натяжение лески» со шкалой и бегунком, «Улов %». Прицел — пунктирное кольцо;
    у точки заброса — подпись, которая видна всегда и меняется на ходу («Заброс сюда», «Дальше не добросить»,
    «Косяк рыбы!», «Тут не вода»), над ней маленький белый указатель. Панели размывают картинку под собой только
    на «высоком» качестве и не на телефоне (класс `blur` на `body`). На телефоне плашка улова стоит наверху, под названием
    места (внизу — джойстик и кнопки), наживка в плашке листается касанием, чип удочки открывает снасти.
    **Маршрут на мини-карте** (`route.js`, `navStep` в `main.js`): в лодке с эхолотом — к ближайшему косяку, с полным садком
    или из открытого моря — домой, к причалу; пешком с уловом — пунктир к торговцу. Путь по воде ищется по сетке
    проходимости (клетка 4 м, по `canSail`; считается понемногу, по 3 мс за кадр), выпрямляется и скругляется только там,
    где срезанный угол тоже идёт по воде; на карте — розовая линия и расстояние. Меню пока в прежнем стиле (этап 20).
  - `audio.js` — звук: записи и синтез. Записи сделаны в ElevenLabs и обработаны `tools/sounds.py` (нарезка,
    выравнивание громкости, петли без шва); лежат в `public/audio`: четыре отдельных файла (всплеск, поплавок на воде,
    трещотка катушки — из неё же одиночные щелчки подмотки и трещотка фрикциона, — обрыв лески), общая дорожка
    коротких звуков `sfx.webm` (шаги по доскам и песку, заброс, поклёвка, подсечка, улов, монеты, щелчки меню…) и
    петли `loop-*.webm` (море, дождь, ветер, сверчки, мотор, водопад, костёр). Где в дорожке какой звук и откуда докуда
    крутить петлю — в `sounds.json`; он попадает в сборку. У звука может быть несколько вариантов (шаги): берётся
    случайный, но не тот, что в прошлый раз (`one()`); петли подгружаются, когда впервые понадобились (`bed()`), водопад
    и костёр слышны вблизи и с той стороны, где они есть (`place()`). Каждый звук сначала пробует запись и только
    потом синтезирует: чего нет в `sounds.json` (или браузер не прочёл файл), играет синтез, как раньше. Сигналы
    игроку — поклёвка, опасность, удача — остаются синтезом в тон музыке. На общем выходе стоит ограничитель,
    чтобы несколько громких звуков разом не хрипели. **Удар лодки о преграду** (`thud()`) — один тяжёлый удар: запись
    собрана из слоёв разных дублей (низ и тело, треск дерева), под ней низкий толчок, следом брызги и откат волны, а
    море и музыка на миг отступают (`duck()`); слабый удар и удары подряд в ту же преграду — глухие, тихие и редкие,
    иначе выходит стук в дверь. Удар слышат и те, кто не за рулём: о нём всем в комнате уходит событие
    (`boat` → `bump`: ход, место удара). Пассажир слышит и чувствует его как рулевой — в полную силу, с тряской камеры
    и вибрацией; остальные — со стороны: тем тише и глуше, чем дальше (до 80 м), и с той стороны, где он случился
    (`via()` — общий выход для такого звука; удары подряд у каждой лодки считаются отдельно). Брызги от сильного удара
    видят все. Так же слышен **мотор чужой лодки** неподалёку (`motorNear()`, до 70 м) — вторая петля из той же записи.
    `npm run test:sound` проверяет записи в настоящем браузере: файлы читаются, каждый
    звук на своём месте и с тишиной по краям, у петель нет шва, на события играют нужные куски, в записи удара лодки
    ровно один удар.
  - `music.js` — музыка, которую сочиняет сама игра: ре мажор, аккорды по такту, поверх — «калимба» (прогулка по
    пентатонике фразами и паузами). Слушает игру (`audio.mood`): при вываживании добавляются пульс баса и шейкер,
    на тугой леске — тревожная нота, с легендой гармония уходит в си минор, ночью и в дождь нот меньше.
    Громкость — в настройках («Музыка», на нуле не расписывается). Сигналы игры настроены в тот же строй.
    `npm run test:music` проигрывает минуту музыки в файл без звуковой карты и сверяет по числам: громкость,
    ноты только из ре мажора, бой громче и ярче покоя, ночью нот меньше; заодно — что записи читаются.
- Прогресс хранится в браузере игрока (`localStorage`) и, если у сервера есть база, — на сервере (см. выше).

## Модели

Сырые модели делает Tripo по описаниям из `art/models.json`: `node tools/tripo.js` (ключ — в `.env`, расход кредитов —
в `art/tripo/state.json`, сырые файлы в репозиторий не попадают). `node tools/optimize.js [id]` приводит их к виду игры:
наибольший размер 1, стоит на земле; сетка упрощена, текстуры в WebP, геометрия сжата; моделям локации делается дальняя
копия без текстуры (`<id>.lod.glb`). Результат и список (`manifest.json`) лежат в `public/models/`.
Где у модели сиденье, вывеска или комель, меряют скрипты из `tools/dev/` — по этим замерам модели и расставлены.
Окнам, которые ночью светятся, в `art/models.json` задают `glow` — коробки со стёклами (их находит
`tools/dev/windows.mjs`): `optimize.js` рисует по ним карту свечения, днём она погашена.

Текстуры земли и камня (`public/tex/*.webp`) рисует `node tools/paint-textures.js [папка для просмотра]`: мазки травы,
каменная кладка, песок, тропа — бесшовные, в игре умножаются на цвет вершин.

Герой — модель со скелетом и тремя анимациями (стойка, шаг, бег): `tripo.js concept → model → rig → anim`, затем
`optimize.js`. В `art/models.json` у героя: `about` — строка на экране «Персонаж», `tall` — рост относительно обычного
(1,76 м вместе с шапкой), `eye` — высота глаз от первого лица, `fp` — цвета запасных рук и `fp.k` — размер рук героя
в кадре. Эти сведения без пересборки моделей обновляет `node tools/optimize.js --meta`. Портреты запекает
`node tools/bake-icons.cjs --faces` (игра должна быть запущена локально).

## Проверки

```bash
npm test                        # правила, сервер, причалы и зоны моря, сохранения, таблица рекордов и комнаты после перезапуска (на Postgres в памяти)
npm start & npm run test:play   # одиночная игра в настоящем браузере, все экраны
npm run test:coop               # двое в одной комнате: лобби, голос, улов друга, обрыв связи
npm run test:devices            # телефон (управление пальцами), страница без захвата мыши, пробная версия без сервера
npm run test:warm               # после заставки не собирается ни одного шейдера: лобби днём и ночью, рыбалка, ночь, дождь (-- low | high)
npm run test:cloud              # сохранение на сервере в браузере: два устройства с одним кодом, расхождение, таблица рекордов
npm run test:sound              # записи звуков: файлы, места в общей дорожке, швы петель, что играет игра
npm run test:frames             # пустые кадры: что лежит в холсте к моменту показа, пока меняются разрешение и качество
npm run test:restart            # перезапуск сервера посреди игры вдвоём: выкладка и падение — оба возвращаются в ту же комнату (сервер запускает сам)
npm run test:music              # музыка, проигранная в файл: громкость, строй, настроения
npm run balance                 # заработок в минуту и исход поединков по наборам снастей
```

Для автопроверок у страницы есть параметры: `?q=low|medium|high` — качество, `?h=13` — час суток,
`?ts=3` — ускорение времени, `?norender` — без отрисовки.

Свой TURN для голоса можно подключить переменными окружения `TURN_URLS`, `TURN_USERNAME` + `TURN_CREDENTIAL`
или `TURN_SECRET`.
